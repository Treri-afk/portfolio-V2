# 0008 — Déploiement sur le VPS personnel (nginx + Docker)

- Statut : accepté (18/10/2026)
- Contexte : le portfolio remplace l'ancien site de `paulabraham.fr`, sur le VPS qui héberge déjà ARKADE et d'autres projets (nginx en frontal, Cloudflare devant le domaine, Node 20 sur l'hôte). GitHub Pages a été écarté : sous-chemin `/portfolio-V2/` et aucun moyen d'exécuter l'API de contact.
- Décisions :
  - **Un script, lancé depuis le Mac** : `deploy/deploy.sh`, sur le modèle de celui d'ARKADE. Il passe `npm run check`, construit le site avec `VITE_SITE_URL` et `VITE_API_URL` de production, copie par `rsync`, relance l'API, publie le site et vérifie les pages publiques.
  - **Site statique** dans `/var/www/portfolio-v2` (propriété root, lecture seule pour nginx). Les 404 servent `__spa-fallback.html`. Assets en cache un an (noms hachés), médias 30 jours.
  - **API dans Docker** : image officielle `node` à la version de `.nvmrc`, épinglée par digest (l'hôte n'a que Node 20). Conteneur `portfolio-api` : système de fichiers en lecture seule, code monté en lecture seule, utilisateur non root, `cap-drop ALL`, `no-new-privileges`, mémoire et PID limités, `--restart unless-stopped`. Réseau bridge isolé (pas d'accès aux autres services en loopback du VPS), port publié sur `127.0.0.1:3050` seulement, CPU limité, `/tmp` en `noexec`. Pas de Dockerfile tant que l'API reste un seul processus sans build : à revoir avec PostgreSQL.
  - **Secrets** : le `.env` de production vit uniquement sur le VPS (`chmod 600`). Le script n'envoie aucun `.env*` ni ne l'écrase ; il s'arrête s'il manque.
  - **Garde-fous** : refus de déployer un arbre non commité (`ALLOW_DIRTY=1` pour forcer), `.nvmrc` doit correspondre à la version de l'image (le digest prime sur le tag).
  - **nginx** (`--nginx`, versionné dans `deploy/nginx/`) : `CF-Connecting-IP` cru uniquement depuis les plages Cloudflare publiées (régénérées à chaque installation), plages validées (format CIDR, nombre minimal), quota `limit_req` sur `/v1/contact`, tout autre `/v1/` en 404, HTTP redirigé vers HTTPS, HSTS, `nosniff`, `X-Frame-Options: DENY`. Les trois fichiers installés sont sauvegardés ; si `nginx -t` échoue, ils sont restaurés (ou retirés au premier déploiement) avant tout rechargement.
- Conséquences : un déploiement dure environ deux minutes et ne touche à aucun autre site du VPS. L'ancien site reste dans `/var/www/portfolio` (et son ancienne API sur le port 3008, non relayée) jusqu'à suppression manuelle. Pas de CSP ni de `Permissions-Policy` pour l'instant : à ajouter avec le hash du script de thème. Le compte SSH a `sudo` et le groupe `docker` (équivalents root) : à restreindre.
